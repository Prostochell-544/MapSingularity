# MapSingularity — архитектура

## 1. Конвейер подготовки (сервер, `sv_director.lua`)

```
IDLE ─► DISCOVER ─► DOWNLOAD ─► MOUNT ─► PRECACHE ─► SYNC ─► READY ─► TRANSIT ─► changelevel
  ▲         │           │          │          │          │        │         │
  └── Fail ◄┴── skip ◄──┴── skip ◄─┴── skip ◄─┘          │        │         └─► Rollback ─► READY
     (отсев по рейтингу бесплатный; до 4 скачиваний в раунде, 3 раунда)  таймаут   портал
```

Запуск: автоматически через `ms_auto_fetch_delay` секунд после `InitPostEntity` (если на
сервере есть люди), вручную `ms_force_fetch [id]`, или спавном `roulette_portal` из меню.
При неудаче с `ms_auto_fetch 1` — повтор через 3 минуты.

### DISCOVER — `sv_workshop.lua`
1. Источник id:
   - `ms_collection` задан → `ISteamRemoteStorage/GetCollectionDetails` (POST, без ключа), случайные 50 детей;
   - иначе `steamworks.GetList(sort, {"map"}, offset, 50, days, "0")` на сервере — случайная сортировка
     (`popular` 0/90/180/365 дней, `trending` 30) и смещение в пределах `ms_discovery_depth`.
2. `ISteamRemoteStorage/GetPublishedFileDetails` пачкой: `result == 1`, `consumer_app_id == 4000`,
   не забанен, тег `map` (без учёта регистра), `file_size ≤ ms_max_size_mb`, на выделенном сервере —
   непустой `file_url`, не в `blacklist.json`, не в `history.json` (последние 40).
3. Рейтинг: `steamworks.FileInfo` → `total ≥ ms_min_votes`, `score ≥ ms_min_score`, без
   `adult_only/nudity/suggestive` (если `ms_allow_mature 0`). Если Steam не ответил за 15 с —
   запасной критерий `lifetime_favorited ≥ ms_min_votes`.
   Для `ms_force_fetch <id>` рейтинг и история не проверяются.

### DOWNLOAD
| Окружение | Маршрут |
|---|---|
| Одиночная игра / listen-сервер | `ms_dl_request` хосту → `steamworks.DownloadUGC` → путь → сервер монтирует. Если хост не ответил/ошибка и есть `file_url` — переход на HTTP. |
| Выделенный сервер | `HTTP GET file_url` → проверка заголовка LZMA (распакованный размер ≤ 4×лимит) → `util.Decompress` → проверка `GMAD` → `data/map_singularity/gma/<id>.dat`. Кэш переиспользуется, если файл новее `time_updated`; хранится 6 последних. |

### MOUNT
`game.MountGMA(path)` → из списка файлов берутся `maps/*.bsp` (кроме текущей карты, имя
только `[%w_%-%.]`), при нескольких — случайная. Проверка `file.Exists("maps/<x>.bsp", "GAME")`.

### PRECACHE — `sv_precache.lua`
1. `file.Open("maps/<x>.bsp", "rb", "GAME")`, сигнатура `VBSP`, версия ∈ {19, 20}
   (иное движок GMod не загрузит — кандидат в чёрный список).
2. Lump 0 (Entity Lump): смещение/длина из заголовка (оба порядка полей lump_t). Если данные
   начинаются с `LZMA` — распаковка Valve-LZMA через перепаковку заголовка в формат Bootil.
   Не распаковалось — карта не отбраковывается, прекэш идёт только по статическим пропам.
3. Lump 35 (game lump) → `sprp` → словарь моделей статических пропов; сжатый `sprp` (флаг 1)
   распаковывается так же, размер потока — из LZMA-заголовка.
4. Извлечение: `model` (*.mdl, спрайты *.vmt/*.spr), ключи материалов (`texture`, `material`,
   `ropematerial`, `spritename`, `detailmaterial`, `overlaymaterial`, …), `skyname` → 6 сторон
   скайбокса, любые значения `models/*.mdl` и `materials/*.vmt`.
5. Только существующие в `GAME` файлы; остальное считается упакованным в pakfile BSP.
   Лимиты: `ms_precache_models` (защита таблицы прекэша на 4096 слотов), `ms_precache_materials`.
6. `MS.Amortize`: каждый тик обрабатываем очередь, пока не исчерпан бюджет `ms_precache_slice_ms`.
   Материалы через `Material()`, модели через `util.PrecacheModel`.

### SYNC
Всем готовым клиентам уходит `ms_prefetch` (id, карта, сжатый JSON списка ассетов ≤ 60 КБ).
Клиент: если `.bsp` уже виден (хост listen-сервера) — сразу прогрев, иначе `DownloadUGC` +
`MountGMA` + прогрев (`ms_cl_precache_slice_ms` на кадр) → `ms_prefetch_done`. Портал открывается,
когда ответили все или прошло `ms_client_wait` секунд. Опоздавшие получают префетч при подключении.

### READY
Портал спавнится в 120–240 юнитах перед инициатором (8 направлений × 3 дистанции, трасса
вперёд + вниз, проверка объёма хуллом), запасной вариант — у точек спавна. После
`game.CleanUpMap` портал восстанавливается.

### Режимы поиска (`ms_search_mode`)
- `top` — «Топ сингулярити»: популярные/трендовые за случайное окно дней, смещение до
  `ms_discovery_depth`, фильтр `ms_min_score` / `ms_min_votes`.
- `universe` — «Холл юнивёрс»: `steamworks.GetList("latest", {"map"})` со случайным смещением по
  всему каталогу (общее число кэшируется, при пустой глубокой странице — повтор в первых 5000).
  Рейтинг не проверяется, только бан и 18+.
- `ms_collection` (если задан) важнее режима.

### Сингулярная пушка и расстановка
- Готовая карта больше не ставит портал «где попало»: по умолчанию (`ms_portal_autoplace 0`)
  хост/инициатор получает `weapon_singularity`, портал ставится выстрелом.
- ЛКМ (`D.GunPlace`): попадание в пол — там; в стену/потолок — отступ на визуальный радиус
  (72) и шаги назад к стрелку по 24 юнита; сначала свободный объём под весь диск
  (72×72×156), затем хотя бы под триггер. Если карта ещё не готова — нестабильный портал на
  месте и запуск поиска. ПКМ (`D.GunReroll`) — новая карта, портал остаётся на месте
  нестабильным. R (`D.GunCollapse`) — убрать портал, готовая карта сохраняется.
- Только админы (`D.Allowed`: консоль, суперадмин, хост). `ms_give_gun` выдаёт пушку.

### Настройки (`cl_settings.lua`)
Q → «Утилиты» → MapSingularity → «Настройки». Значения — реплицируемые конвары
(`MS.CVars` в `sh_config`), изменения уходят `ms_setting` (C→S), сервер проверяет права и
нормализует значение по `MS.Settings`. Кнопки: выдать пушку, крутить рулетку, отменить, статус.

### Портал (`lua/entities/roulette_portal/`)
- **Окно-тоннель:** сфера радиусом 0.33 размера пишет трафарет (с учётом глубины мира); внутри —
  `ClearBuffersObeyStencil` (фон + сброс глубины) и тоннель из радужных колец, звёзд и «света в
  конце», уходящий от наблюдателя (направление = от глаза к ядру). Изнутри сферы маска рисуется
  с обратной отбраковкой. Ядро поднято на 80 юнитов (`ENT.CoreHeight`), чтобы диск не уходил в пол.
- **Вид:** аккреционный диск — 5 колец из лучей (`trails/plasma`) в плоскости, наклонённой на
  18° от «лица» портала; по кольцам бегут яркие сгустки, внутренние крутятся быстрее
  (кеплеровски). 42 частицы падают по спирали и тянутся нитями (`trails/laser`). В центре —
  линза (`effects/strider_pinch_dudv`) и свечение. Нестабильный диск прецессирует и искрит.
- **Притяжение:** общий хук `Move` (сервер + предсказание клиента) тянет живых игроков к ядру
  стабильного портала: радиус 420, ускорение 1100·(1−d/R)² юнит/с². Конвар `ms_portal_pull`
  (FCVAR_REPLICATED). Реестр `MapSingularity.Portals` — чтобы не перебирать энтити каждый тик.
- **Искажение вблизи:** `cl_visuals` в радиусе 450 добавляет FOV до +10°, вихревой блюр и
  закрутку пропорционально (1−d/R)².

## 2. Прыжок (`sv_inventory.lua` + `cl_visuals.lua`)

| t | Сервер | Клиенты |
|---|---|---|
| 0 | касание (StartTouch/Touch + проверка в Think) → `BeginTransit`: всем `GodEnable`, `SetDSP(14)`, `ms_transit BEGIN` | маркер `data/map_singularity/client_transit.json`, звук втягивания, режим `out` |
| 0…1.5 | — | FOV +55° (ускорение t²), вихревой блюр 10 слоёв с закруткой до ~29° и вертикальным вытягиванием (спагеттификация), крен камеры до 28°, обесцвечивание, чёрный по smoothstep |
| 1.85 | `Commit`: снимок живых людей → `map_singularity_state.json`; если есть сетевые клиенты — исходный `sv_loadingurl` + журнал и `sv_loadingurl` := `ms_loading_url`, иначе конвар не трогается (безопасный режим); `changelevel` | сплошной чёрный (`hold`) |
| +20 c | если карта не сменилась — `Rollback` (URL, JSON, бессмертие, DSP, `ms_transit ABORT`) | растворение чёрного за 0.6 с |

Снимок игрока: `hp`, `maxhp`, `armor`, `maxarmor`, `suit`, `god` (до прыжка), `active`,
`weapons[] {class, clip1, clip2}`, `ammo[] {name, count}`. Ключ — SteamID64 (`"singleplayer"`,
если его нет в одиночной игре). Боты не переносятся.

## 3. Прибытие

| Момент | Сервер | Клиент |
|---|---|---|
| загрузка Lua | читает и удаляет JSON; `resource.AddWorkshop(wsid)`; при свежем (≤ 10 мин) state для этой карты — ожидаемые игроки и инвентари | маркер свежий и для этой карты → чёрный с первого кадра |
| `InitPostEntity` | если `server.cfg` перезаписал URL — снова подменяет; таймер `ms_url_restore_timeout` | — |
| `PlayerSpawn` | запись найдена → `PlayerLoadout` подавлен; через тик `StripWeapons/StripAmmo` + выдача | — |
| клиент `InitPostEntity` | `ms_client_ready` → игрок «в игре»; когда все путешественники в игре — `sv_loadingurl` возвращается | — |
| восстановлен ∧ готов | `SetDSP(0)`, `ms_arrival` | растворение чёрного 2.0 с, FOV +18°→0, блюр 0.12→0, звук |
| нет сигнала 15 с | — | чёрный снимается сам |

**Безопасный режим.** `MS.LoadingScreenAudience()` считает сетевых клиентов (всех людей,
кроме хоста listen-сервера; в одиночной игре — 0). Если их нет, `I.ChooseLoadingURL()`
возвращает пустой URL: `sv_loadingurl` не подменяется и не восстанавливается, недоснятая
прошлая подмена снимается, на новой карте таймеры восстановления не запускаются. Решение
пишется в лог («экран загрузки: …») и видно в `ms_status`.

**Метка для хоста.** `ms_client_ready` несёт флаг «у клиента установлен патч экрана
загрузки» (`html/ms_tunnel.js` есть и подключён в `html/loading.html`). Если такой клиент —
хост, `Commit` дописывает в `hostname` невидимый U+2063; патч в странице загрузки видит метку
в `GameDetails` и включает тоннель. Метка снимается, когда хост прислал `ms_client_ready` на
новой карте, при откате, по таймауту `ms_url_restore_timeout` и при любой загрузке Lua без
прибытия. Подробности для пользователя — `docs/HOST-GUIDE.md`.

Журнал `data/map_singularity/loadingurl_ledger.json` живёт, пока URL подменён. Если карта
сменилась не через портал до восстановления — следующая загрузка Lua вернёт исходный URL.

| Сообщение | Направление | Данные |
|---|---|---|
| `ms_phase` | S→C | UInt4 фаза, String текст, Float прогресс |
| `ms_prefetch` | S→C | String id, String карта, String название, UInt32 + Data (Bootil-LZMA JSON `{m=[], t=[]}`) |
| `ms_prefetch_done` | C→S | String id, Bool ok |
| `ms_dl_request` | S→хост | String id |
| `ms_dl_result` | хост→S | String id, Bool ok, String путь (принимается только от адресата текущего запроса) |
| `ms_transit` | S→C | UInt2 тип (1 BEGIN / 2 ABORT), String карта, String текст, Float длительность |
| `ms_client_ready` | C→S | Bool: у клиента установлен патч экрана загрузки хоста |
| `ms_arrival` | S→C | Float длительность, String название |

## 7. Ограничения движка (честно)

- Source 1 не держит две карты: «бесшовность» — это маскировка. Загрузка новой карты всё
  равно идёт, её закрывает чёрный экран загрузки.
- Прекэш на сервере до смены карты не переносит таблицу прекэша (она сбрасывается при
  changelevel). Он проверяет ассеты и прогревает файловый/дисковый кэш; основной выигрыш —
  клиенты, которые заранее скачали и смонтировали карту.
- Тот, кто сам хостит игру (одиночная игра и хост listen-сервера), всегда видит стандартный
  экран загрузки: меню при `IsHostingGame()` вызывает `GameDetails` с URL `127.0.0.1` и
  `maxplayers = 1`, и кастомная страница не открывается. Код меню аддонам недоступен.
  Чёрный до и после загрузки работает; чёрный экран загрузки видят только гости сервера.
- Перед кастомной страницей меню на долю секунды рисует свой фон (30,30,30) и стандартную
  страницу — это вне досягаемости аддона.
- Если `asset://` не отдаёт файлы аддона в вашей сборке — захостите `web/portal_loading.html`
  по https и пропишите адрес в `ms_loading_url`.
- `server.cfg` может перезаписывать `sv_loadingurl` при каждой загрузке карты; аддон повторно
  подменяет URL в `InitPostEntity`, но порядок выполнения консольного буфера нужно подтвердить в игре.
